# «Хорары» — браузерная версия 2.5

**Открыть приложение 2.4 в браузере (без входа в ChatGPT):**
https://rawcdn.githack.com/SuimaK/Horar/93da9c3e60809899c8ea1b9822e7546fb091cb57/index.html

Готовая статическая сборка находится в ветке `browser-build` и обслуживается публичным CDN из GitHub. Сам GitHub Pages ещё не включён: текущему подключению недоступна административная настройка Pages. Карты и вопросы остаются в локальном хранилище браузера; при смене адреса они переносятся через JSON-экспорт/импорт.

Последовательно интегрированы методические обновления **v1.2 → v1.3 → v1.4 → v1.5 → v1.6 → v1.7 → v1.8 → v1.9**. Астрономические расчёты выполняются на устройстве через Swiss Ephemeris WebAssembly / Moshier. Сервер для работы приложения не нужен.

## Новое в 2.5: корректирующий пакет метода 2.0.1

- Достоинства и рецепции сохраняются при неопределённой секте. Неоднозначный триплицитет получает варианты и отметку `SECT_DEPENDENT`, без выбора секты наугад. Перегрин Фроули отделён от отсутствия положительных достоинств и от изгнания/падения.
- Адаптивный поиск локализует корни, ингрессы и станции. Учитываются события до точного аспекта; совпадение в пределах 2 секунд требует отдельной проверки. Станция не становится автоматической рефранацией.
- Новый поиск основной пары выходит за 30-дневный предпросмотр до границы знака, с техническим пределом 365 суток; последующие контакты отмечены `AFTER_INGRESS_REVIEW`. Общая полнота остаётся `SEARCH_INCOMPLETE`.
- Добавлен канал антисций: неподвижные зеркальные точки исходной карты, только соединение/оппозиция, дедупликация одновременных зеркальных свидетельств. Достоинства берутся по телесным положениям.
- Отдельный трактуемый дом по правилу ≈5° перед куспидом в том же знаке; исходные дома и куспиды не переписаны. Сила дома и радость пересчитываются по трактуемому дому.
- Граница эксплуатации ±65° действует и в форме, и в расчётном API. Ошибка вне диапазона: `LATITUDE_OUTSIDE_VALIDATED_REGION`. Куспиды проверяются на конечность, порядок и полный оборот.
- Скорости Олешко сохранены как средние прямого движения; справочные нетто-скорости Фроули показаны отдельно там, где есть данные. Пороги 0,8/1,2 обозначены проектной эвристикой.
- Дополнительная геометрия передачи света использует историю текущего знака в пределах 365 суток, без обязательного ограничения четырьмя днями. Показаны дуга отделения, последовательности двух будущих контактов/цепочки и рецепции собирающей планеты; отсутствие одного приёма не запрещает путь автоматически.
- Отдельные признаки строгой пустоты Луны и контекстной проверки длинного промежутка, перечень неполноты акцидентальных факторов, подпись `DISPLAY_ORB_CONVENTION` для графических 6°.

Новые сведения находятся в `evidence.method_correction` (`MethodCorrectionEvidence 2.0.1`), с собственной JSON Schema и provenance правил. Исторические `ChartSnapshot 1.0`, чистые контракты/профили v1.1 и v1.2 сохранены. При импорте старый численный снимок проверяется и сохраняется; тексты и утверждения из файла по-прежнему не принимаются на веру, новый слой пересчитывается. Вопросы вне ±65° отклоняются при новом расчёте/импорте без изменения координат или существующего архива.

Карьерный предварительный слой использует исправленные сведения напрямую. Для чистого модуля отношений v1.8 выделен адаптер: только достоверные рецепции и исправленные условия; варианты секты остаются в 2.0.1. Технические поля `source_module` сохраняют протокол v1.8, конкретный адаптер указан в `calculation_adapter`. Прежний предпросмотр v1.5 остаётся отдельным совместимым протоколом для регрессии и разметки v1.6, а не полным поиском.

Проверены 136 тестовых функций JavaScript, включая 47 приёмочных случаев пакета и 7 независимых численных сценариев Python/WASM. Это проверка реализации, не экспертная приёмка метода или точности предсказаний. Подробнее: `CORRECTIVE_2_0_1.md`, `QA_REPORT.md`.

## Новое в 2.4: карьера v1.9

В типе вопроса **«Работа и карьера»** доступны 11 сценариев: получение работы, принятие предложения, сохранение/потеря/смена работы, повышение, сравнение вариантов, отношения с начальником, зарплата, выплата и условия труда. Сценарий, критерий события, состояние занятости, трудовая роль и источник денег выбираются отдельно.

Для предварительного разбора выберите **X дом без производного**, зафиксируйте роли и подтвердите предварительную пару I/X. VI вместо X отклоняется с пояснением. При зарплате от работодателя XI и II показаны раздельно; оплата клиента и собственные деньги не назначаются XI автоматически. Роль начальника, альтернативной работы или повышения не выводится автоматически.

**Граница доверия v1.9:** браузерная галочка не создаёт `EXPERT_LOCKED`. Независимого серверного реестра экспертно утверждённых ролей нет, поэтому итоговый модуль возвращает ожидание утверждения. Рецепции и условия текущей карты показаны отдельно как **предварительные вычисленные сведения**, не как одобренные экспертом свидетельства. Критерий пользователя сохраняется с `expert_reviewed=false`; событийные пути контактов не используются для найма, увольнения или выплаты.

Исходные контракты v1.0–v1.8 и их чистые модули сохранены; карьерный вопрос использует отдельную схему `question_career_browser.schema.json` (`1.9-browser`). Подробности: `DEVELOPMENT_V1_9.md`.

## Новое в 2.3: модули v1.6–v1.8

- **v1.6:** прямые, передающие и собирающие пути имеют устойчивые идентификаторы и перечень условий для разметки. Автор может записать обоснование, оценку рецепций/возможности действия и каждого промежуточного контакта. Сохранение создаёт новую ревизию; исходный вопрос и прежние записи не меняются. Личность и квалификация автора не удостоверяются, оценка пути не становится прогнозом события.
- **v1.7:** в форме контакта отдельно выбираются сценарий и критерий события. Только согласованный поддерживаемый маршрут допускается к v1.6. Ответ на сообщение, возобновление общения, примирение, возвращение в дом и возвращение к отношениям не подменяются обычной встречей. Неподдерживаемые темы получают отдельную причину ограничения.
- **v1.8:** новый тип «Отношения» содержит восемь сценариев. Рецепции каждой стороны, событийный путь и условия/качество показаны отдельно. Свидетельства берутся из текущего расчёта v1.1/v1.2/v1.3 и связываются с ролями и картой. Введённые или импортированные реестры и флаги экспертного утверждения не принимаются.

Для разметки обычного контакта откройте «Разбор», затем путь в разделе v1.6 → «Добавить разметку автора». Все обязательные условия проверяются заново. Полный перечень полей и статус метода описаны в `DEVELOPMENT_V1_6_TO_V1_8.md`.

Событийные критерии отношений пока не утверждены экспертом: примирение/начало/расставание не получают готового ответа даже при наличии рецепций. Станции косвенных путей, личность экспертов, редакция Фроули 2014 и реальные исходы остаются неподтверждёнными. Положительная рецепция не является доказательством реальных чувств, согласия или события.

Старые JSON-архивы поддерживаются. Вопросы нового типа «Отношения» используют явно выделенный браузерный контракт `question_browser.schema.json` (`schema_version=1.8-browser`); старые контракты ядра не переписаны под новый тип. Схемы и Python-модули из переданных пакетов хранятся отдельно от пользовательских данных.

Добавлены явная классификация чувствительных тем и метка учебного примера. Подробная привязка к BUG-001…006 — в `FIXES_QA_2_2_1.md`. В том выпуске ещё не было v1.6; её разметка и арбитр добавлены в 2.3, как описано выше.

## Что изменилось

- **v1.2:** сверены акцидентальные правила и эталонный ответ; сохранены достоинства и направленные рецепции v1.1.
- **v1.3:** свидетельства собраны по участникам. Проверяются карта, исходный хэш, версии, подтверждённые роли и соответствие рецепций. Условные YES/NO из Python-функции `evaluate_contract` не подключены к клиентскому приложению.
- **v1.4:** карта повторно вычисляется перед анализом; сравниваются все семь планет, скорости и двенадцать куспидов. Поиск точных аспектов использует реальные эфемериды с трёхчасовым шагом и уточнением корней.
- **v1.5:** отдельные сценарии встречи, звонка/контакта и сообщения от конкретного человека. Рассчитываются лунная последовательность в текущем знаке, роль Луны, станции основных сигнификаторов, прямые и косвенные геометрические кандидаты. Промежуточный контакт отмечается для проверки и не считается автоматическим запретом.

## Как пользоваться новым разбором

1. В форме выберите тип **«Контакт / встреча»**, затем конкретный сценарий.
2. Укажите отношение к человеку. Поддерживается только конкретный человек без специальной социальной роли; применимость I/VII подтверждается отдельно.
3. Выберите **VII дом без производного**, подтвердите роли и применимость I/VII. Укажите окно поиска 1–30 суток.
4. Постройте карту и откройте **«Разбор»**. Там доступны свидетельства по участникам, лунная последовательность, прямые кандидаты, передача/собирание света и станции.

Для доставки посылки, получения ранее отправленного письма, прибытия посетителя, вопросов о супруге/родственнике/начальнике и вопросов от третьего лица выводится конкретное ограничение. Поиск по неподтверждённой паре I/VII не запускается. Для других типов вопросов сохранён прежний общий режим карты и прямого поиска.

Это расчёт свидетельств, **не автоматическое суждение «да/нет»**. Даты относятся к точным аспектам; они не выдаются как сроки событий. Фроули используется в ранней предварительной редакции, таблицы Олешко обозначены отдельно; аудит издания Фроули 2014 не завершён. Адаптивный численный поиск локализует корни и относительные станции, но не является доказательством полноты для произвольной траектории. При недостаточном окне статус отсутствия лунных аспектов остаётся неопределённым.

## Архив и обновление

Сохранены ключ `horary-iphone-records-v1` и форматы резервных копий `horary-iphone-archive-v1` / `horary-iphone-record-v1`. Старые записи открываются без новых полей. Чтобы получить новый разбор старой карты, создайте **ревизию**: исходный вопрос и прежний результат сохраняются. Новые настройки сценария входят в экспорт и восстанавливаются при импорте. При импорте, открытии и экспорте карта повторно рассчитывается; планеты, куспиды, настройки и исходный хэш сравниваются с расчётом. Тексты разбора, роли и флаги из файла не используются: формируется новый результат. Изменённые карты и готовые прогнозы отклоняются. Если весь архив не прошёл проверку или запись в хранилище не удалась, прежние записи остаются без изменений. Для проверки нужен загруженный локальный WASM-модуль; работа без сети возможна при сохранённом кеше.

Перед сменой домена экспортируйте архив: браузерное хранилище привязано к адресу сайта. Автоматическое сохранение в облако не добавлено.

## Запуск и публикация

Требуется Node.js **22.22.2+** в ветке 22 либо **24.15+**; зависимости зафиксированы в `package-lock.json`.

```bash
npm ci
npm test
npm run build
npm run dev
```

`dist/` — готовая статическая PWA, включая WebAssembly и service worker. После первой успешной загрузки кеш может обеспечивать работу офлайн; Safari может очищать кеш и локальные данные. На физическом iPhone это обновление ещё не проверялось.

Для `SuimaK/Horar` предусмотрен workflow `.github/workflows/pages.yml`. Загрузите исходники в корень репозитория и выберите **Settings → Pages → Source: GitHub Actions**. Workflow устанавливает зависимости, запускает тесты, собирает `dist` и отправляет его в Pages. Размещение только несобранных `index.html`/`src` не запустит приложение.

- **136 тестовых функций JavaScript:** старые расчёты, порт v1.3, ограничения v1.5, реальные WASM-эфемериды, форма, ревизии и экспорт/импорт.
- Реальные WASM-положения и куспиды сопоставлены с тремя исходными Python-эталонами.
- Полный смысловой результат демонстрации v1.5 сопоставлен с предоставленным Python-ответом с численной погрешностью менее `0.000002` суток/градуса для проверяемых чисел.
- Исходные Python-наборы: v1.2 — 46 тестов (один предусмотренный пропуск), v1.3 — 38, v1.4 — 45, v1.5 — 65. Ошибок нет.
- 88 условных сценариев v1.3 выполнены в исходном Python-модуле: 82 совпали со старыми ожиданиями, шесть — с отдельно поставленными нормативными поправками. Это проверка контрактов, не прогнозной точности.

Дополнительно 67 маршрутизаторных, 38 сценариев отношений и 54 карьерных сценария сравниваются с полными результатами исходного Python, а не только ожидаемыми статусами. Исходные пакеты v1.6/v1.7/v1.8 прошли 54/83/54 теста; новый оригинальный Python-пакет v1.9 прошёл 70 тестов.

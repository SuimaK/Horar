# «Хорар» — браузерная версия 2.1 для iPhone

**Статус:** исходный проект без серверного API; автоматизированные тесты доменной логики проходят. **Публикация и фактический запуск WebAssembly в Safari ещё не проверены** — перед использованием нужен успешный GitHub Pages build и тест карты на устройстве.

## Архитектура

- Картографический расчёт выполняется целиком на устройстве через `@swisseph/browser` **1.3.1**, Swiss Ephemeris WebAssembly (Moshier). Приложение не отправляет вопросы в серверный API.
- Зодиак: тропический, геоцентрически; семь традиционных планет; дома Региомонтануса.
- Учитывается скорость планет, ретроградность, локальные и будущие прямые точные аспекты (с геометрическим уточнением по реальным эфемеридам до долей секунды в рамках 6-часового сканирования).
- Поиск геометрии ограничен 30 сутками, не считается полным хорарным прогнозом. Реализованы вычисления эссенциальных достоинств и рецепций v1.1, а также акцидентальные свойства v1.2 (см. ниже). Но не выполняется полный синтез свидетельств, помех, перевод/собирание света и 88 семантических контрактов. Автоматические ответы «да/нет» и сроки отключены.
- Локальный архив использует **прежний ключ** `horary-iphone-records-v1`, поддерживает чтение старых ревизий и экспорт/импорт в **прежнем формате** `horary-iphone-archive-v1`. Если домен поменяется, браузерное хранилище не переносится автоматически — используйте JSON-экспорт.
- `sw.js` формируется на сборке, кеширует JS/CSS/WASM/иконки. После успешной первой загрузки может работать без сети, если Safari сохранил cache. Очищение данных Safari удалит локальный архив.

## Обновление методики v1.1 и v1.2 (интеграция 2.1)

- `src/evidence.mjs` — независимый порт представленных Python-модулей достоинств, рецепций, акцидентальных состояний и проверки привязки ролей на JavaScript.
- `src/profiles/` — **два именованных профиля с исходной атрибуцией**: `OLESHKO_1999_P55` и `FRAWLEY_EARLY_ACCIDENTAL_V1_2_WITH_OLESHKO_SPEED_REFERENCE`. Эти профили не выдают себя за полностью сверенное исправленное издание Фроули 2014.
- В разделе **«Разбор»** теперь отображаются все семь планет: собственные достоинства/слабости, направленные рецепции, взаимность, радости планет, сильные/слабые дома, скорость, ретроградность, сожжение/казими/лучи, фаза Луны. Никакие баллы не превращаются в «прогноз». Для скрепления рецепций с участниками должны быть подтверждены и заблокированы роли.
- **Секта** определяется высотой геометрического центра Солнца над горизонтом, а не часом на часах. Если высота в пределах ±0.5°, алгоритм не угадывает DAY/NIGHT: v1.1 остаётся неопределённым, но v1.2 выводится с пометкой экспертной проверки. Близость к горизонту необходимо проверить в астрономическом приложении.
- При экспорте JSON добавляется необязательный объект `result.evidence` (`sect_info`, `essential`, `accidental`, `joined`, `role_receptions`). Сами форматы ChartSnapshot, RoleAssignment и `horary-iphone-archive-v1` не изменены. Старые карты остаются без нового объекта; для перерасчёта надо создать ревизию старой карты (архив сохраняет прежнюю запись).
- `tests/evidence.test.mjs` сравнивает **полные эталонные ответы** из обоих релизов Python, включая их профильные хэши и контрольные SHA-256. 12 новых тестов + 11 исходных = **23/23 PASS**. Исходные тесты Python: v1.1 — 164/164, v1.2 — 46 успешных с одним пропущенным (опциональная интеграция).
- Профиль v1.2 использует **эвристические пороги скоростей**: они не численные правила Фроули. Мгновенная скорость не подтверждает станцию. Не реализованы точный расчёт станции, дополнительные факторы, осада, звёзды, полный сюжетный синтез.

Важно: содержимое исходных ZIP и их документация **не включены целиком** в этот проект для публичной выкладки. Взяты только явно необходимые для работы профили, JSON-схемы и синтетические тестовые примеры. Предполагается, что исходные методические документы остаются у владельца проекта.

## Публикация на GitHub Pages — без установки программ

1. Создайте **отдельный** репозиторий GitHub, например `horary-browser` (не используйте репозиторий с рецептами). Для бесплатной Pages-публикации, как правило, нужен **публичный репозиторий**. Не загружайте туда внутренний исходный пакет ТЗ, тестовые личные карты и другие приватные документы.
2. Загрузите **содержимое этой папки** в корень репозитория, включая `.github/workflows/pages.yml`, через браузер GitHub. Отправьте в `main`.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Автоматическая сборка установит необходимые зависимости **на серверах GitHub**, не на вашем iPhone или компьютере. После удачного workflow `Publish Horary PWA to GitHub Pages` появится адрес вида `https://ИМЯ.github.io/horary-browser/`.
4. Откройте адрес в Safari. При желании выберите **Поделиться → На экран Домой**. Это необязательно, обычная вкладка Safari тоже работает.
5. Постройте контрольную карту и сопоставьте с эталонными числами из `tests/reference.json`: пример `2026-11-11T08:51:00Z`, широта `55.7558`, долгота `37.6173`, Солнце `228.976073°`, куспид I `271.231679°`. При отклонениях сборку нельзя считать принятой.

**ВНИМАНИЕ О ЛИЦЕНЗИЯХ.** `@swisseph/browser`/Swiss Ephemeris распространяется по AGPL-3.0. Публичная публикация и распространение совместного программного продукта требуют соблюдения AGPL-3.0, в том числе доступности соответствующего исходного кода; для закрытого приложения может понадобиться профессиональная лицензия Astrodienst. Проверьте условия перед публикацией. Исходники этого проекта (в том числе `src/`) можно разместить открыто только при наличии соответствующих прав на них. Никакой приватный методический архив не включён. См. `THIRD_PARTY_NOTICES.md`.

## Для разработчика (не требуется пользователю iPhone)

```bash
npm install
npm test
npm run build
```

`dist/` — полностью статический сайт для GitHub Pages (включает `assets/swisseph.wasm`). **Не публикуйте только исходные файлы без сборки**. Не передавайте в Pages папку backend прежнего проекта.

### Что проверено здесь

- 23/23 unit-тестов, включая контролируемую модель позиций, даты/смещения, производные дома, ревизии, безопасный статус и корни аспектов.
- Сформированный ответ v1.0 удовлетворяет 5/5 исходным JSON Schema (предыдущая внешняя Python-проверка); примеры модулей v1.1 и v1.2 проходят ещё 5/5 профильных проверок схем.
- `node --check` для всех собственных JavaScript-модулей.

### Что НЕ проверено здесь

- **Не запускался `npm install` и итоговый Vite build**: доступ к npm registry в среде создания пакета отсутствует. Следовательно, адаптер и WebAssembly в реальном браузере пока не прошли интеграционное тестирование. При проблеме не выдавайте страницу как работающий калькулятор — смотрите ошибки Actions.
- Нет визуальных испытаний на физическом iPhone, Safari и офлайн-кешировании, а также проверок поведения при обновлениях.
- Не проверена семантическая состоятельность окончательной интерпретации (она отключена).
